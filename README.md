<h1 align="center">project-bath</h1>

<p align="center">由 Agent 执行的阶段性项目清理方法：清掉失效代码与上下文，先保存原件，保护用户改动。</p>

给 Agent 一段明确的范围，它会先找有证据的清理候选，保存原字节或冷归档，再分批清理、验收并交接恢复位置。只想了解问题时，可以先做零写入审计。

## 核心亮点

| 结果 | 方法 |
|---|---|
| 清理有依据 | 核查真实入口、引用与行为；证据不足暂留，不凑清理量 |
| 原件可回取 | 写入前核验工作区原字节、备份 hash、批次清单和可逆补丁 |
| 用户改动有保护 | 建基线保留已有改动；恢复先比较本轮后状态，不覆盖后续内容 |
| 边界明确 | 默认跳过第三方代码、生成物、锁文件、公开API变更、迁移、依赖移除和架构拆分 |

## 使用示例

一个实际可用的起点是只读审计本仓的原始 Skill 与许可证。加载下文的 `SKILL.md` 后向 Agent 发出：

```text
按 project-bath 只读审计当前仓库的 SKILL.md 和 references/LICENSE。
核对入口、规则是否仍有效及引用，不写入项目，不创建归档。
只在会话给出候选、证据与暂留理由。
```

本次对这两份原文件的审计没有发现足以清理的失效内容：它们分别是有效方法入口与MIT许可依据，因此保留两者、零写入、不建空归档。你的项目结果取决于真实证据；“无需清理”也是正常结果。

## Quick Install / 获取

需要能读取文件、遵循 Skill 指令的 Agent 宿主；授权清理时还需在限定项目范围内操作文件。这个仓库提供方法文件，没有独立CLI、自动清理程序或必须安装的Python/Node运行环境。

```sh
git clone https://github.com/qq2743759880/project-bath.git
cd project-bath
```

让宿主直接加载当前目录的 [SKILL.md](SKILL.md)。若宿主有自己的 Skill 发现目录，按它的规则放入整个目录并保留 `references/LICENSE`；本仓不承诺所有宿主共享同一自动安装路径。

## Quick Start / 快速开始

在克隆目录启动你的 Agent，先让它读取 `./SKILL.md`，再执行上面的只读审计请求。这条首次使用路径只读取方法与许可文件，结果在会话给出，不需要测试框架或清理脚本。

准备开始真实清理时，把范围写成具体项目路径和保留项，例如：

```text
读取 project-bath Skill，给当前项目的文档与过时上下文做一次阶段性清理。
保留我的未提交改动、有效约束与失败证据。先建基线和列有依据候选；
授权范围内的可逆项先保存原字节或冷归档，再分批清理并验收。
不改公开API、依赖、数据库迁移或架构。最后说明暂留项和恢复位置。
```

这是交给 Agent 的请求，不是 shell 命令。它仍需遵守目标项目的审批边界；范围不清时先澄清。每批次只解决一个问题，检查若出现新增失败只回退本轮。

## 什么时候使用，什么时候不使用

适合用户明确要求阶段性清理：移除证据充分的死代码、等价重复、过时注释/TODO/路径，或让已结束、错误的上下文退出活动入口。只想了解候选时选只读审计。

普通功能开发与架构重构不触发这个 Skill。它也不以永久删除、自动清空归档、移除依赖或全局 reset/clean 作为默认清理方式。零文本引用不是死代码证明；规范年代久或代码违反规范，也不是规范失效的证据。

## 实际怎样清理

[流程说明与图](docs/workflow.md) 展示：定范围 → 建基线 → 找候选 → 先保存 → 清理 → 验收 → 交接，以及只读、暂留、备份核验失败和本轮回退分支。步骤全部来自原始 Skill，是 Agent 的执行方法，不代表独立后台自动化。

验收会核对受影响检查、公开行为、用户改动、旧事实是否退出实际加载、归档是否退出构建及原件可回取。未知加载通道应明确说明；修改文件不会清空已读对话，需要时保存已验证交接，再使用新上下文。

## 为什么先备份，如何恢复

未提交改动可能只存在于当前工作区，不能用 Git HEAD 代替原件。整文件移入冷归档；局部编辑先备份实际原字节并核对SHA-256，记录批次 `manifest.json` 和仅含本轮改动的可逆补丁。无Git也保留备份和差异。

恢复先比较目标与本轮后状态：一致才直接恢复；后续改动通过本轮补丁比对、合并。不能安全合并就保留两份和现状、说明冲突，同名新文件不可覆盖。[恢复说明](docs/recovery.md) 给出具体请求和边界。
